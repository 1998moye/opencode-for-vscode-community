# OpenCode for VS Code 开发规范

## 硬性维护性要求

- 代码必须优先保证可读、可定位和可修改，不能为了短期交付把多个功能堆入同一文件。
- 每个模块只承担一个清楚的职责，并通过小而稳定的接口隐藏实现复杂度。
- `OpenCodeRuntime` 是应用级唯一测试接缝，只负责接收用户意图、协调内部模块并发布归一化状态，不直接实现 CLI 进程、Server 请求、事件解析、Webview 协议或界面渲染。
- CLI 与服务生命周期、OpenCode SDK 适配、会话、消息、事件归一化、VS Code 集成、Webview 协议和各界面区域必须放在独立模块中。
- 生产适配器和测试适配器只能出现在真实外部依赖接缝；禁止为每个函数增加没有变化价值的接口和转发层。
- 新功能应优先扩展现有深模块；一个文件开始承担第二类业务职责时，必须先拆分再继续实现。
- 测试通过最高层稳定接口观察行为，不测试私有函数、内部调用次数或 React 实现细节。

## 当前模块职责

- Runtime：意图路由、状态发布、模块协调。
- CLI：可执行文件检测、版本判断和进程启动。
- Server：本地服务生命周期、健康检查和连接安全。
- Gateway：OpenCode SDK 请求、目录路由和协议类型转换。
- Session：会话选择、创建和历史加载。
- Message：消息发送、中止、增量事件与重建。
- Surface：VS Code Webview 生命周期和双形态同步。
- Webview：纯展示、可访问交互和本地渲染状态。

## 审查门槛

- 一个模块是否只有一个可以用一句话说明的职责。
- 调用者是否只需要学习小接口，而不需要理解内部适配器。
- 功能修改是否集中在对应模块，还是需要同时修改多个无关文件。
- 是否出现巨型条件分发、重复协议转换、跨层状态写入或循环依赖。
- 行为测试是否仍然只通过 `OpenCodeRuntime` 接缝完成。

## 打包发布

- 打 VSIX 必须使用 `npm run package` 或 `npm run vsix`，禁止直接调用 `vsce package`。
- 上述命令会先执行 `scripts/bump-version.mjs` 递增补丁版本号，再构建并打包。
- 每次功能性改动后打 VSIX，应在 `CHANGELOG.md` 顶部补充对应版本说明。
